# Хогвартс: карточная дуэль — этап 3: награды и заявки

В архиве **полный сайт** и серверная функция Appwrite. Сайт сохраняет дизайн и 15 исходных карточек.

## ВАЖНО: перед публикацией

Эта версия требует настройки серверной функции Appwrite. Если просто загрузить архив на GitHub, каталог продолжит работать, но выдача карт покажет сообщение об отсутствии ID функции. Не используйте выдачу карт до окончания настройки. Функция и база ещё не развёрнуты и не проверены в вашем облачном проекте.

### 1. Загрузить сайт на GitHub

Распакуйте ZIP и загрузите **содержимое** архива в репозиторий, заменив одноимённые файлы. Render Static Site: Build Command `echo ready`, Publish Directory `.`. Папка `backend` — исходники функции Appwrite, не самостоятельный сайт.

### 2. Определить свой Appwrite User ID

Зарегистрируйте свой аккаунт на сайте (логин и пароль). В Appwrite → Auth → Users откройте запись вашего пользователя и скопируйте **User ID**. Это не пароль и не Project ID. Только этот аккаунт станет главным администратором.

### 3. Создать функцию

В Appwrite Cloud → Functions → Create function. Runtime: **Node.js 22** (или совместимая более новая версия с поддержкой JSON import attributes). Подключите GitHub репозиторий; укажите Root directory: `backend`, entrypoint `src/main.js` (если запрашивается), build/install command `npm install`. Функция должна иметь **Execute access: Users / authenticated users**, не Guests/Any.

В Settings функции задайте переменную окружения `ADMIN_USER_ID` со значением вашего User ID из шага 2. Также установите (если не проставляются автоматически):
- `APPWRITE_PROJECT_ID` = `6ad75c6d0024af9d8bab`
- `APPWRITE_ENDPOINT` = `https://fra.cloud.appwrite.io/v1`

Для функции включите scopes **databases.read**, **databases.write**, **users.read** (в настройках разрешений функции). Appwrite передаёт серверный ключ в заголовке `x-appwrite-key`. Не вставляйте ключи API в HTML/JS и не присылайте их в чат.

После развёртывания функции скопируйте **Function ID** из её Settings.

### 4. Подключить ID функции к сайту

В `app.js` найдите строку:

`const REWARDS_FUNCTION_ID='REPLACE_WITH_FUNCTION_ID';`

Замените **только** `REPLACE_WITH_FUNCTION_ID` на ваш Function ID (это публичный идентификатор, не секрет). Сохраните файл и загрузите изменённый `app.js` на GitHub.

### 5. Создать структуру базы

Войдите на сайте под **главным административным аккаунтом**. Откройте «Администрирование» → «Создать структуру базы». Если панель пока показывает ошибку отсутствующей базы, кнопка настройки всё равно доступна. Дождитесь сообщения об успехе. Затем подождите 30–60 секунд, чтобы Appwrite подготовил атрибуты, и перезагрузите сайт.

Будут созданы база `hogwarts_duel` и коллекции `profiles`, `reward_codes`, `redemptions`. Прямые клиентские разрешения на чтение и запись **не выдаются**; все операции идут через серверную функцию.

**Если bootstrap возвращает ошибку:** не создавайте базу наугад. Пришлите текст ошибки, будем исправлять по шагам.

### 6. Проверка

1. Зарегистрируйте тестовый аккаунт игрока.
2. Войдите главным администратором, откройте «Администрирование» → «Обновить заявки».
3. Подтвердите аккаунт игрока.
4. Сгенерируйте код «Выбранная карта» или «Случайная карта».
5. Войдите игроком и активируйте код в «Награды».
6. Откройте «Мои карты»: количество должно увеличиться.

## Реализовано в этом этапе

- Подтверждение/отзыв допуска пользователей (проверка на сервере).
- Генерация до 30 одноразовых кодов за раз.
- Режимы: конкретная карта, случайная карта, случайная ещё не полученная карта.
- От 1 до 10 карт в одном коде; дубликаты разрешены.
- Личная коллекция со счётчиками экземпляров.
- Базовый серверный журнал выдачи: `reward_codes` (кто создал, когда, основание, кто активировал) и `redemptions` (кому, что и когда выдано).
- Для нынешних 15 карт, у которых ещё не задана редкость, используется «Обычная»; случайный выбор равновероятен **внутри подходящих карт**. Взвешенные вероятности редкости пока не реализованы.

## Ограничения и безопасность

- **Нельзя считать проект полностью готовым до проверки функции в Appwrite.** Развёртывание и фактическая активация пока не тестировались в вашем проекте.
- Логин/пароль используют технический email-идентификатор в Appwrite (без ввода почты). Сброс пароля по почте отсутствует.
- Вход не означает одобрение: выдача наград недоступна до подтверждения.
- Код случайный, одноразовый; хранится только SHA-256 хеш. Полный код показывается администратору один раз при создании.
- Конкурентная активация защищена уникальным ID первой записи о выдаче. При сбое между созданием нескольких записей возможна **частичная выдача**; для строгой транзакционности в будущем потребуется транзакционный механизм и обработка восстановления.
- В этой версии нет отдельного удобного интерфейса просмотра журналов, редактирования карт, колод и дуэлей; данные журналов сохраняются на сервере.
- Настройка «публичная коллекция» пока не открывает доступ другим игрокам: публичные страницы профилей будут отдельным этапом.
- Если вы включите гостевой Execute доступ для функции или клиентские права записи в базу, это нарушит модель безопасности.
